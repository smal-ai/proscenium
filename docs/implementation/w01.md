## Composition

```python
from contextlib import asynccontextmanager

from proscenium.app import create_app
from proscenium.configuration import Settings
from proscenium.copilot import install, router
from proscenium.services import Services

services = Services.create(Settings.load())
# Defaults to the accepted extensions['projects'].settings(project_id) getter.
# An optional database-only policy_resolver can supply an accepted settings record.
runtime = install(services, policy_resolver=None)
app = create_app(services.settings, services=services, routers=[router])

@asynccontextmanager
async def lifespan(app):
    await runtime.start()
    try:
        yield
    finally:
        try:
            await runtime.close()
        finally:
            services.close()

app.router.lifespan_context = lifespan
```

Follow-up on `impl/w01-child`, base `d068ed9`: one cloud root and one required-model
native child successfully read a real planned job through production `get_job`,
using an opaque ID supplied only in the captured selection. No native startup,

Model-facing failures now retain the existing `error` code while returning an
allowlisted actionable message and safe details. Unknown upstream messages,
credentials, headers and exception representations are withheld. Preview failures
can state the public `proscenium-blender-1` CPU/Cycles recipe. The Blender skill also
documents this accepted recipe, stable source/instance IDs, checkpoint/head-CAS
semantics and the proper scoped launcher, without home defaults or dirty-scene
replacement. See the follow-up evidence for exact source hashes and test outcomes.

- `install(services, *, native=None, policy_resolver=None) -> Copilot` installs
  `services.runtime` and `extensions['contexts']`, `['copilot']`, `['execution']`.
  `native` injection is for the offline fault harness. Production leaves it unset.
- `await runtime.start()` restores durable gates and starts the host delivery task.
  It creates **no SDK client/session and sends no model message**. Imports and reads
  are equally quiet. Projects activated later receive the same epoch checks.
- `await runtime.close()` closes admission, stops/reaps the owned native process,
  then settles/cancels host tasks. Cleanup still runs if SQLite persistence fails.
  It never cancels independent jobs or kills unrelated processes.
- `reconcile(project_id)`, `resume(project_id, operation_id)` and
  `stop(project_id, work_id, operation_id)` implement the accepted RuntimeAdapter
  protocol. Resume/Stop identities must already have their durable admissions.
- HTTP routes only admit commands or read SQLite. The delivery task survives a
  request/socket disconnect. Parent lifespan composition is mandatory.

## Private runtime configuration

`Settings.runtime` is never part of ConfigurationView or request context.

| Key | Behaviour |
| --- | --- |
| `cli_path` | Absolute direct `@github/copilot-linux-x64/copilot`. Default is the local worktree platform binary. Its SHA-256 must match the runtime lock. No PATH/npm launcher/download fallback. |
| `lead_model` | Defaults to `gpt-6.1-sol`, requires a non-empty model ID. |
| `worker_model` | **Required explicit choice**. Configure an available economical model for normal use. The bounded proof explicitly used `gpt-6.1-sol`. |
| `worker_tools` | Explicit native/custom tool-name list for `authoring-specialist`. Model policy is always `required`, never parent fallback. |
| `profile_id` | One configured live profile, default `authoring`. Unsupported requested profile IDs fail truthfully rather than being ignored. |
| `skill_directories` | Absolute adapted skill roots. Default is this checkout's `agent/skills`. Packaged installs must configure the deployed resource path. |
| `mcp_servers` | Exact SDK server configurations, including an operator-provided `mcp-for-blender==2.0.0` command connected to its external live add-on. No add-on/Blender/service installation or replacement occurs. |
| `max_continues` | Default 5, cannot be less than 5. |

Unknown keys are rejected. Create **and** resume set memory disabled, session-store
retrieval disabled, sandbox off, infinite sessions enabled, Autopilot continuation
enabled, streaming, adapted skills, and `.proscenium/tool-output` spilling. Shell is
not excluded. Cold loads set `continue_pending_work=False`. Callbacks/tools/hooks
are registered in create/resume, before native execution can start.

Authentication is the official existing login, `use_logged_in_user=True`.
An allowlisted process environment excludes provider/GitHub token variables and
disables login-shell environment imports. No token is extracted or forwarded.

### Abrupt backend death

The SDK launches `copilot/launcher.py` through the application interpreter. The
launcher establishes Linux `PR_SET_PDEATHSIG(SIGKILL)`, verifies the original
backend PID/start identity to close the fork race, fsyncs its private PID/start
record, then **execs the verified direct native binary**. No launcher process
remains. The SDK's owned PID is the actual native PID, unlike the npm launcher.

The parent-death signal applies to that native process, not a process group or
independently admitted render/provider worker. Resume checks the recorded original
PID/start identity and executable. A surviving original backend is owner_conflict.
An attributable orphan may be fenced through its pidfd, but execution remains
blocked until exit is observed. Linux is required for this boundary.

The real SIGKILL test observed the actual exec-native PID stop, preserved a
separately owned process, and verified the native `/proc` identity disappeared.
Normal live clients were also stopped/reaped. This is not a claim about arbitrary
independent subprocess cancellation.

## Durable execution and context

- RequestRecord retains the complete immutable submission, accepted timestamp,
  context ID, effective profile/task and current receipt. POST returns its receipt.
  Retries return the current projection and never launch a second native send.
- Queue admission reserves its stable work/generation task and FIFO order before
  external effects. A WorkRecord is created only when delivery is reserved, so held
  requests do not create multiple active work records or block settled switching.
  Only one root work is delivered. Steer retains its own context
  and the original work/task. `client_turn_id` is correlation, **not deduplication**.
- SQLite dispatch/outbox/attribution commits precede sends and callback replies.
  Events join by native session plus event/message/tool/agent identities. Model
  `turnId` is scoped by originating message because the runtime reuses turn IDs
  for later root requests. Late outcomes retain their original work.
- Native user echoes enrich the existing request, never create another chat entry.
  Out-of-order public events are staged with an allowlisted payload, then joined
  after their native identity is bound. Unresolved attribution prevents settlement.
- Live duplicate event bodies are checked by digest. Cold history checks existing
  public projections separately because native load rewrites private system-message
  content. Missing final public text can be repaired without replaying inference.
- Root task/turn completion is only a candidate. Settlement additionally checks
  accepted steering, native children/tools, decisions, the last delivery's native
  idle observation and an empty native queue. Independent jobs keep their own state.
- Images are ready/hash/path/decode checked under configured count/byte/pixel limits.
  The SDK attachment list includes every annotation's own clean target, markup and
  mask, ordered clean images then markup then masks. Original snapshots are unchanged.
  Binary masks require lossless 8-bit luma PNG, correct target dimensions and values.
  Spatial hits retain their own camera/version/frame/object instance and mapping
  source digest. No annotation is retargeted to the current viewport.
- Approved findings require their exact clean target images in the original
  attachments. Queue/Steer acceptance calls W05's
  `validate_and_submit_findings(tx, request_id, approved_findings)` **inside that same
  transaction**. Missing W05 support rejects the submission. Raw unapproved findings
  never appear in a model-facing review response.
- Permission callbacks join the real native permission event's request ID and tool
  invocation. They do not invent a request ID from a fingerprint. Input callbacks
  likewise require the native request/tool join. Owner CAS/fingerprint checks and
  native callback delivery are separate records. Native completion events only mark
  delivery acknowledged when the exact answer/result matches.
- Routine tools follow the owner policy. Consequential command patterns request an
  exact owner decision. Known secret/outside-file reads are denied. This pragmatic
  policy is **not** an OS sandbox or a general shell/network security guarantee.

### Stop and Resume

Stop durably fences Queue delivery and new Steer, invalidates unanswered decisions,
and records pause ownership. Its phases are admission, exclusive pause acquisition,
settling all admitted sends, one Abort, owned-message reconciliation and quiescence.
Waiting for sends **before** Abort prevents a delayed immediate send from entering
the runtime after that one cancellation. Conditional withdrawal uses the original
text and native messageId, never the native queue-item ID. False withdrawal is not
recorded as successful removal. Confirmation requires an empty pending/steering
state, settled sends/children/tools and observed idle (or previously settled work).

Lost pause/Abort/send acknowledgements retain uncertainty and close the gate.
Exclusive pause acquisition is never blindly repeated. The owned runtime can be
terminated to prevent further execution without inventing an unknown outcome.

- Fresh project plus a new direct owner request explicitly authorises its first
  delivery. It does not release a stopped/restarted project's work.
- Boot/epoch changes retain held requests and put interrupted work awaiting_resume.
- `reconcile_only` loads/reads exact history without opening admission.
- `continue_work` retains the original work/task and holds unrelated queues. A new
  continuation message has its own operation correlation and original context. It
  never resends the original Queue body.
- `release_held_queue` requires no interrupted active work. Only this adapter's
  proven live pause is released. Another owner's pause is never generic cleanup.
- Resume retries expose the current durable CommandReceipt state. Missing native
  history remains native_session_missing and appears on the original request card.
  There is no automatic new-conversation or uncertainty-reset action.

Absent services return capability_unavailable. Each method receives a host-derived

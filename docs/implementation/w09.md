## Trusted API graph

`tools.image_to_3d.candidate.graph(reference_artifact_id)` flattens the official template's
subgraph. Offline tests compare all internal links and the principal widget parameters to
the retained official source. Changes are only the registered-image placeholder, seed
placeholder and output prefix. Core nodes and parameters:

1. `ImageOnlyCheckpointLoader` selects the exact renamed official checkpoint.
2. `LoadImage` consumes `artifact:<input_artifact_id>`, not a description of a filename.
3. `CLIPVisionEncode`, crop `center`, feeds `Hunyuan3Dv2Conditioning`.
4. `ModelSamplingAuraFlow`, shift `1`, sampling `flow`, wraps the checkpoint model.
5. `EmptyLatentHunyuan3Dv2`, resolution `3072`, batch `1`.
6. `KSampler`, 20 steps, CFG `8`, Euler, normal scheduler, denoise `1`, explicit `$seed`.
7. `VAEDecodeHunyuan3D`, `num_chunks=8000`, octree resolution `256`.
8. `VoxelToMesh`, `surface net`, threshold `0.6`.
9. `SaveGLB` directly consumes `MESH` and writes `mesh/proscenium-e04` outputs.

`MeshToFile3D` exists but is unnecessary because the installed `SaveGLB` accepts `MESH`
directly. Its actual UI/history output is `outputs["82"]["3d"]`, not `images`.
This is real image conditioning followed by shape decoding, not a rendered image or
an image-plane export. It remains a proposed graph until inference runs successfully.

Helpers perform no inference and install nothing:

```bash
python3 -m tools.image_to_3d graph --reference-artifact-id e04-conditioning
python3 -m tools.image_to_3d inspect-weights
python3 -m tools.image_to_3d preflight \
  --catalog docs/evidence/w09/object-info-redacted.json \
  --reference-artifact-id e04-conditioning
python3 -m tools.image_to_3d inspect-history /absolute/path/to/exact-prompt-entry.json
python3 -m tools.image_to_3d inspect-glb /absolute/path/to/generated.glb
```

The saved independent-service catalogue **must fail preflight** because its checkpoint
list is empty. The helper does not insert the newly downloaded weight into that service's
inventory. The exact-model schema-positive test is explicitly synthetic.

`bind` only accepts the trusted graph, one verified conditioning filename and an exact
JSON-safe seed. `preflight` checks actual sockets including SaveGLB's multi-type input,
node availability, checkpoint choices and numeric bounds. `inspect_glb` verifies a bounded
embedded GLB 2 container with finite positions, valid indexed triangles and non-collapsed
local bounds. It rejects external buffer/image dependencies. This narrow CPU checker is
not Blender import proof, topology assessment, source publication or visual acceptance.

## Original W07 integration proposal, superseded by the extension above

At preparation time W07 rejected `capability=image_to_3d` before admission. The bounded
extension now implements that capability. No standalone `/prompt` command or second budget
ledger is supplied.

Proposed private host plugin interface, using existing JSON records and transport:

```python
class GenerationCapabilityPlugin(Protocol):
    capability: str  # "image_to_3d"
    job_kind: str    # "mesh_generation"

    def bind_graph(self, workflow: dict, *, input_artifact_ids: list[str],
                   uploaded_names: dict[str, str], seed: str,
                   model_ids: list[str]) -> dict: ...

    def preflight(self, bound_graph: dict, object_info: dict) -> None: ...

    def output_descriptors(self, exact_prompt_history: dict) -> list[dict]: ...

    def inspect_output(self, staged_path: Path) -> dict: ...
```

The plugin has **no** submit, reserve, lifecycle, claim, status-write or publication method.
The integration owner adds host-owned capability selection inside the existing provider
service. This package supplies the pure implementation pieces in `workflow.py` and `glb.py`,
not an already registered backend plugin.

## Feasibility risks and explicit limits

- Native Hunyuan nodes and a public supported checkpoint are established. ROCm/gfx1151
  inference, host model fit, mesh extraction, GLB production and Blender import are not.
- The advertised CUDA/VRAM figures in upstream documentation are not measured guarantees
  for this AMD unified-memory workstation. Independent resident services may leave
  insufficient system memory despite a reassuring GPU counter. Do not unload them to fit.
- This workflow generates **untextured shape only**. No texture, UV quality, manifoldness,
  clean topology, retopology, rigging or back-side accuracy is claimed. Record actual empty
  material/texture inventories without pretending this is a failure of file import.
- Centre cropping and background content affect conditioning. Use a single visible object
  on a simple background for the first proof. Any later preprocessing must be an explicit
  recorded derivative, not an undeclared custom-node/model dependency.
- A prepared graph and green synthetic tests do not establish E04, M10 or product dispatch.
  Only the coordinator can accept the actual image → mesh → Blender → checkpoint/publication
  proof or escalate a failed candidate for an owner scope decision.

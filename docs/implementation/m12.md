`pending`, no `copilot.sends` record, one total send reservation. It was never
reposted or given another identity.

`6c5999f` moved the gate to the actual SDK `CopilotSession.send` boundary. The
existing held request was explicitly released once. The test uses the pinned
`JsonRpcClient.request(..., on_response_inline=...)` seam to arm after a known
control ping and pause the actual stdout reader before its next read. It does not
decode/intercept auth, proxy the CLI or bypass its executable hash.

Observed on that second real send:

- The actual stdout was an OS pipe. Its descriptor was physically closed while
  `session.send` was pending. Two real JSON-RPC futures were pending, the read gate
  had not expired, and SDK transport closure was observed.
- Native history contains an unfinished `userPromptSubmitted` hook matching the
  second public test input, but **no corresponding `user.message`** or message ID.
- Pausing every stdout read also blocks the inbound hook callback which this
  application registers **before native admission**. The hook cannot finish while
  its transport reader is paused. This is actual pre-admission transport loss, not
  evidence of an accepted native message whose ACK was lost.
- Host restart was quiet. Explicit owner `reconcile_only` retained the same session
  ID and send count 2, but correctly ended `outcome_uncertain` / attribution

- A late private fixture `get_events` raced cleanup after that uncertain Resume
  and returned `JsonRpcError -32000`. No success, safe rejection or admission
  correlation is inferred from that error.

**Accepted-send ACK-loss recovery remains open.** No third send or speculative

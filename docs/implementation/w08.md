## Owned implementation

| `agent/skills/unity/` | Specialist instructions and W01 registration proposal, not profile edits. |

The tool consumes the accepted F00 `Services`, `Caller`, `JobService`, `SourceService` and closed JSON
contracts. It implements no second database, auth, upload, job, router or source checkpoint service.
Its recipe/export/worker receipts are private tool artefacts, not replacement public DTOs.

## Integration callable

```python
run_unity_job(
    services: Services,
    caller: Caller,
    admission: dict[str, Any],  # exact JobAdmission JSON
    *,
    project: str,              # e.g. unity/Walkthrough
    recipe: dict[str, Any],
    editor: Path,              # trusted configured official executable
    action: str = "import",    # import | validate | build | playtest | repeat-proof
    timeout: int = 600,         # 1..600 seconds
) -> dict[str, Any]
```

`repeat-proof` is a fixture-only operation. It intentionally creates an acceptance sentinel and
imports twice. Do not run it on an authored production scene. `playtest` is the bounded F05 test
suite, not a generic acceptance proof for arbitrary world geometry.

The return contains the existing `JobRecord` as `job`, the contract `UnityResult` as `unity` when
actually produced, and the attempt's evidence location/worker observation. The result wrapper is
tool-local. Model-facing/public outputs use the existing contracts. Unity API `Assets/...` paths are
qualified beneath `project` for catalogue results, so they resolve from the active Proscenium root.
The Editor recipe itself keeps Unity's asset-relative scene path.

### Exact host invocation shape

```python
from pathlib import Path
from tools.unity.jobs import run_unity_job
from tools.unity.workflow import input_digest, make_recipe, prepare, verify_materialisation

project_id = caller.project_id
root = Path(services.registry.get(project_id)["path"])
source_service = services.extension("sources")
materialised = source_service.materialise(project_id, pinned_version["version_id"])
entry = verify_materialisation(materialised, published_source_closure)
prepare(root, "unity/Walkthrough")

# The trusted Blender authoring/export wrapper executes the fixed script against entry.
# It records the closure digest and writes a project-owned export, not a live source edit.
recipe = make_recipe(
    root, "unity/Walkthrough",
    source_id=source_item_id,
    source_version=pinned_version,
    closure=published_source_closure,
    export_path="unity/exports/environment.json",
    spawn=(0.0, 0.92, -2.0),   # fixture example, not a universal spawn default
    camera="perspective",
    pipeline="urp",
)
admission = {
    "schema_version": "1.0",
    "operation_id": original_operation_id,
    "project_id": project_id,
    "job_id": admitted_job_id,
    "kind": "unity",
    "target": {"target_id": target_id, "version": pinned_version, "shot_id": None},
    "input_digest": input_digest({"project": "unity/Walkthrough", "recipe": recipe, "action": "import"}),
    "input_artifact_ids": ready_export_artifact_ids,
    "execution_profile_id": configured_execution_profile_id,
}
result = run_unity_job(
    services, caller, admission,
    project="unity/Walkthrough", recipe=recipe,
    editor=configured_editor_path, action="import", timeout=600,
)
```

The host supplies the published closure/version and caller. The adapter checks the stored version's
item/closure, materialises through the accepted service, verifies hydrated source files and frozen
export hash/digest, and admits through `services.jobs.admit` **before** an external Editor starts.
The parent integrates any ready-export artefact registration and publication through accepted tools.

### Trusted export command

The host supplies all paths. This script runs inside Blender, not ordinary CPython:

```text
blender --background --factory-startup --disable-autoexec --threads 4 \
  PINNED_MATERIALISED_ENTRY.blend --python-exit-code 1 \
  --python INSTALLED_TOOLS/unity/export_blender.py \
  -- MATERIALISED_ROOT PROJECT_OWNED_EXPORT.json SOURCE_CLOSURE_DIGEST
```

Rehash the materialisation before export. The exporter opens no live authoring scene, saves no
source, rejects external libraries/textures and ambiguous IDs, and applies the evaluated world
transform and scene unit scale. Blender XYZ becomes Unity XZY. Triangle winding reverses for the
handedness change, accounting for negative source transforms. Textures and look-dev are deliberately
not reproduced. One base colour per mesh and a usable Standard/URP Lit material satisfy this scope.

## Project preparation and import behaviour

```bash
python -m tools.unity.workflow inspect --root ACTIVE_ROOT --project unity/Walkthrough
python -m tools.unity.workflow bootstrap --root ACTIVE_ROOT --project unity/Walkthrough
python -m tools.unity.workflow prepare --root ACTIVE_ROOT --project unity/Walkthrough
```

- These commands launch no Unity process. Native actions are deliberately not CLI choices.
- Bootstrap is a fresh-project scaffold only. It never overwrites existing package/settings files.
  It requires existing host authorisation for supported package population. Actual scene/settings
  content is saved through the Editor APIs.
- Tested resolved packages: Input System **1.20.1**, URP/Core/Shader Graph **17.3.0**, Test Framework
  **1.6.0**. Exact transitive versions are in the evidence package lock. No root manifest/lock changed.
- No default depends on a home directory, game checkout, private asset or installed Editor path.
- Preparation rejects active project Editors/lockfiles and locally edited installed scripts. It
  records installed hashes, copies only its own namespace and never removes `.meta` files.
- The source key selects `Assets/Proscenium/Generated/<source-key>/`. Only its marked root in the
  selected scene is replaced. Mesh/material assets are mutated in place, preserving GUIDs. Unrelated
  scene roots and other source-ID subtrees remain untouched.
- Imports save a named `source-manifest.json` containing pinned version/closure/export identity.
- A current dirty scene or Play mode is rejected by the C# API entry point. Batch launching into an
  already open/locked project is rejected by project-path process checks, not broad Blender guards.
- Perspective and orthographic cameras both support mouse yaw/pitch. R returns to the supported
  declared spawn. Controller centre is its GameObject origin, height 1.8 m, radius 0.25 m and skin
  width 0.02 m. Import rejects an obstructed or unsupported spawn rather than guessing a safe one.

## Recovery, cancellation and publication

- Admission returns the existing job on repeat. Attempt directories are exclusive durable launch
  intents. Existing/live/uncertain attempts are reconciled, not relaunched. Changed recipe/action
  requires a new admission/input digest. A verified local failure/cancellation can use shared retry.
- The supervisor records job/attempt/source/input identity plus PID, process start ticks and boot
  ID. It owns one native process group, waits/reaps it and writes observed exit codes. Missing exit
  evidence never becomes a fabricated code or success.
- `reconcile_unity_job(services, caller, job_id)` checks exact worker or originating tool-work scope,
  validates request/receipt identity, observes surviving processes and settles actual output. A dead
  supervisor with an ambiguous native outcome remains uncertain. The parent must reconcile before
  resume and must not assume the lost supervisor still enforces its timeout.
- `cancel_unity_job(services, caller, job_id)` is a parent outbox callback after F00 commits
  `cancel_requested`. It signals only the verified owned supervisor, or its verified surviving
  native group. Terminal cancellation needs the supervisor's actual interruption receipt.
- Terminal-resource release is idempotent, including the DB-update/claim-release crash window.
- `checkpoint_unity(services, caller, CheckpointRequest_JSON)` delegates to the existing source
  checkpoint service. It permits authored Unity paths and excludes Library/Temp/Logs/Builds and
  UserSettings. The parent constructs publication from that receipt's commit, complete source
  closure, pinned ancestry and returned `UnityResult`. Failed/not-run playtests can still publish.

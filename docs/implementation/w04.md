## Composition

```tsx
import { StudioApp } from "./app/StudioApp";

<StudioApp components={{
  review: ReviewWorkspace,
  outliner: Outliner,
  catalogue: CatalogueBrowser,
  storyboards: StoryboardBrowser,
  critic: CriticPanel,
}} />
```

- The exported signature is `StudioApp({ components }: { components?: StudioComponents })`.
  Types come unchanged from integration-owned `src/api/studio.ts`.
- `main.tsx` currently calls `capturePairing()` before mounting standalone `StudioApp`.
  Keep that call before mounting the parent's composed app. It removes the private
  `#pair=` fragment synchronously and records the original pairing operation/client nonce.
- One `ApiClient` instance supplies all injected components. It uses same-origin cookies,
  the paired CSRF token and explicit mutation identities. The browser never reads the
  HttpOnly owner cookie or receives tool/worker capabilities.
- Left tabs mount storyboard, outliner and catalogue surfaces respectively. Right Critic
  receives the current immutable selection input. Copilot stays mounted but hidden while
  Critic is open, preserving its draft and pending upload state.
- Exactly one central review component is mounted. W05 owns its review mode controls and
  keyboard handling. The standalone fallback supplies three honestly unavailable modes,
  initial Keyframes and keyboard `1`/`2`/`3`, without launching anything.
- `onContextChange` records the generated `TurnSelection`. `onQueue` captures a deep copy,
  fresh context/request IDs and capture time before context admission and Queue submission.
  Annotation snapshots keep their own targets. There is no annotation retargeting here.
- The fallback catalogue reads all item/version pages using generated operations.
  Selecting a version pins its identity. Publications refresh catalogue metadata without
  selecting a new version. Version/context selection survives reload in browser-private
  storage. Injected components receive actual jobs and an event-driven `refreshRevision`.

## Implemented behaviour

- Linear Minimal surfaces, locally bundled Inter and JetBrains Mono, 48 px header,
  280 px navigation, 360 px assistant and internally scrolling panels at 1920 × 1080.
  Font notices ship at `/licences/fonts.txt`. No external fonts or archived mockup code.
- Saved project traversal, workstation-path create/open, verified-location rebind command
  and a separate explicit Activate action. No HTML directory picker or implicit model work.
  Activation failure leaves the existing project and its controls available for settlement.
- Pairing requires an explicit browser action. Ambiguous pairing retries reuse the original
  operation, code and client nonce across reload. Successful pairing erases the stored code.
  Private authentication/recovery records use the `proscenium.owner.` local-storage prefix,
  never project records, agent context or public events. CSRF is restored across reload/tabs.
- Configuration shows actual configured lead/worker profiles, service endpoints/models and
  available/offline/unknown states. Profile and generation-limit changes use the existing
  project settings operation and affect future work only. There is no unsupported global
  service-edit endpoint or service lifecycle control.
- Original Queue/Steer/Stop history comes from paginated `RequestRecord` reads, including
  never-dispatched messages. Request events replace the same keyed entry. Assistant events
  are grouped by native session/agent/message ID, with complete text replacing deltas.
  Native echoes do not append another user message. Only allowlisted public text is shown.
- Tool, native-specialist and observed usage records remain separate. Unknown model, token,
  cost or cost-unit data is labelled unavailable. No private reasoning is rendered.
- Queue is the default. Steer requires selecting the current active work explicitly.
  Stop is a separate request with its own durable pending slot and bypasses a pending Queue.
  Stop confirmation is shown from request/work records, never inferred from browser closure.
  Independent jobs have separate cancellation requests and state.
- Held-request cancellation, exact fingerprint/revision owner decisions, input answers,
  permission decline/approve-once and explicit generation-budget extensions are implemented.
  Approval does not select creative output or bypass its original requirement.
- Resume offers `reconcile_only` by default, `continue_work` and `release_held_queue` explicitly.
- PNG/JPEG/WebP uploads use stable upload IDs, server readiness checks and explicit
  same-upload retry. Unready/failed uploads block composer submission. Ready images have
  role controls, authenticated previews and removal. Original request contexts are fetched
  separately and retain their original images and annotation targets.
- An ambiguous prompt acknowledgement retains the complete frozen submission/context and
  draft. Explicit reconciliation GETs the original request first. Only a confirmed 404
  permits retrying that same request/context identity. No connection/reload event sends a
  prompt automatically. Typing during an acknowledgement does not erase the newer draft.
- Non-prompt commands retain their immutable operation/body after an uncertain response.
  Changing inputs while such a command is retained is rejected locally, not silently sent
  under the old identity. Retry the original action and inputs first. Definitive 4xx
  validation/CAS rejections clear the unadmitted command, except timeout and conflicting
  operation reuse. A subsequent explicit action can then use corrected inputs.
- Initial hydration reads snapshot, all requests/items/jobs and the full append-only public
  journal. Socket subscriptions continue from the in-memory applied cursor. Sequence and
  native-session/event deduplication protect replay. Gaps trigger HTTP replay, expired
  cursors trigger snapshot plus replay from zero, and reconnect refreshes metadata. The
  last cursor is also recorded privately, but a full page reload deliberately reconstructs
  conversation from zero rather than trusting a cursor without its corresponding text.
- Socket cleanup only detaches. It never submits Stop, Resume, cancellation or model work.

## Integration and remaining limits

1. Parent composes W05/W06 components in `main.tsx` and retains `capturePairing()`.
   Missing components deliberately show unavailable states. W04 does not implement a
   proxy viewer, annotation editor, storyboard authoring or VLM review engine.
2. Parent can integrate this suite under `make test-browser` and add a pinned `@types/node`
   if browser-test static typechecking becomes part of that command. No shared manifests,
   lockfiles, generated schemas/client or composition seam were changed here.
3. Live backend integration must verify all W01/W02 state/CAS responses, configuration
   profiles, owner cookies and media responses. Synthetic acceptance is not evidence that
   those packages, native cancellation or a real provider are operational.
4. Request history and events are fully traversed for correctness. Very large journals
   will need a parent-approved projection/virtualisation strategy, not an arbitrary
   truncation which loses original user messages.
5. In-memory incomplete upload bytes are not retained across browser closure. Ready
   attachment identities and text drafts are retained. The owner must reselect an image
   interrupted before a ready artefact was acknowledged. No incomplete upload is submitted.
6. Non-prompt commands with a retained uncertain outcome intentionally require their
   original action/inputs. There is no speculative “discard and execute again” control.
   A definitive stale-revision rejection clears that unadmitted command. The owner must
   refresh and explicitly act again. It never silently creates a new approval or operation.

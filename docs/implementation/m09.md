## Concrete defects and narrowly scoped fixes

### Reasoning exhausted the bounded structured response

The initial owner review reached `google/gemma-4-e4b` with the accepted adapter. It returned
HTTP 200 in 10.7863 seconds with `finish_reason=length`, 512 completion tokens, 509 reasoning
tokens and empty `message.content`. The adapter correctly refused to treat private reasoning
as findings and completed the job as failed.

The provider now requests OpenAI-compatible `reasoning_effort: "none"` only when the exact
loaded model's native metadata advertises reasoning option `off`. This is a per-request
inference option, not a loaded context/KV/batch/TTL or saved-profile change. No automatic
retry or token-budget increase was added.

The **second allocated inference** actually exercised this fix: zero reasoning tokens,
192 completion tokens, complete structured content in 4.5630 seconds. This is measured
compatibility with the inspected local service, not a claim about every OpenAI-compatible
provider. The first owner review remains failed in history.

### Structured output allowed an invalid measured artefact reference

The native-origin response contained a visual finding and a width finding. The width was
640 pixels, but its `kind: measured` evidence named `m09-clean-target`, not the explicitly
supplied `m09-pixel-telemetry`. Runtime relationship validation correctly rejected the
whole completion with `scope_denied`. No partial finding was stored or forwarded.

The generated response schema now constrains target indices to the actual input indices
and evidence to role-specific variants: visual IDs from supplied images and measured IDs
only from supplied telemetry. Without telemetry there is no measured variant. Runtime
validation remains authoritative, and no response is repaired after inference.

This schema refinement was added **after both calls**. It has targeted offline regression
coverage, not a third live call. A renewed bounded allocation is necessary to validate the
full corrected positive journey.

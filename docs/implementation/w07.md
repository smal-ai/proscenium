**Integration follow-up:** base `029e56aabe8b79c830cc2abaad1c5acdd36e1b48`,
14 November 2026. Target identity resolution and the exact-worker W02 bridge below replace

`76d845133c44c8759f50299160322b717e60d00a` and accepted W05 review backend

## Composition and exact signatures

```python
from proscenium.providers import install, router, register_provider_artifact
from proscenium.catalogue import install as install_catalogue
from proscenium.reviews import install as install_reviews

install_catalogue(services)
install_reviews(services)
providers = install(services, registrar=lambda caller, body:
    register_provider_artifact(services, caller, body))
app = create_app(settings, services=services, routers=[router, ...])
```

Neither imports nor `install` nor job/configuration reads perform HTTP calls, start a
background worker, load a model or change an independent service. `install` is idempotent.
It registers the service at `services.extensions['providers']`, which the SDK consumes.
The provider router owns exactly:

| Operation | Route | Response |
| --- | --- | --- |
| `submitGenerationJob` | `POST /internal/v1/generation-jobs` | `JobRecord`, 202 first acceptance, 200 retry. |
| `requestOwnerReview` | `POST /api/v1/projects/{project_id}/reviews` | `ReviewTicket`, 202 first acceptance, 200 retry. |
| `requestToolReview` | `POST /internal/v1/reviews` | `ReviewTicket`, 202 first acceptance, 200 retry. |
| `completeToolReview` | `POST /internal/v1/reviews/{review_id}/complete` | `ReviewTicket`, 200. |

All JSON arguments below are the existing generated contracts' JSON representation,
validated with the normative schemas. A generated RootModel caller passes
`command.model_dump(mode='json')`. There is no alternative DTO.

```python
ProviderService.submit(caller: Caller, request: GenerationSubmit_JSON) -> tuple[JobRecord_JSON, bool]
ProviderService.request_review(caller: Caller, request: ReviewRequest_JSON) -> tuple[ReviewTicket_JSON, bool]
ProviderService.complete_review(caller: Caller, request: ReviewComplete_JSON) -> tuple[ReviewTicket_JSON, bool]
ProviderService.pump(project_id: str, job_id: str | None = None) -> list[JobRecord_JSON]
ProviderService.start(project_id: str, *, interval: float = 1) -> None
await ProviderService.close() -> None
install(services, *, registrar=None, client: httpx.Client | None = None) -> ProviderService
```

The tuple boolean is `replayed`. `pump` is synchronous and performs bounded HTTP outside
transactions. A parent can use `await asyncio.to_thread(providers.pump, project_id)` or call
`start` from its running event loop **after explicit Resume and reconciliation**. `start`
does not open the F00 gate. `close` waits for an in-flight call rather than cancelling a
thread during submission. The parent must await it before closing F00 services. The
default client has a 120-second timeout, disables environment proxies and redirects and
does not retry mutations. An injected client remains the parent's lifecycle responsibility
and must not automatically retry POSTs.

## Required parent bindings

1. **F00 execution gate:** admission uses `JobService.create`, including its gate guard.
   Parent composition must supply an explicitly opened execution context for owner Review
   as well as native work. Startup/restoration must not open it implicitly.
2. **Frozen Queue allowance and target resolution:** W07 lazily binds a missing task policy
   from `copilot.effective[work.originating_request_id].generation_attempt_limit`. W01
   already freezes that value before delivery. No current default, project file, UI state
   or tool-supplied limit is consulted. Existing explicit
   `bind_generation_task(tx, task_id, limit, targets)` integrations remain supported.

   `GenerationSubmit.settings` accepts only `{}` or `{"target_slot": SelectionSlot}`.
   The existing normative `SelectionSlot` identifies a real item, published storyboard
   version/shot/frame or published sequence version/entry. W02's immutable source API
   materialises and validates authored documents outside the admission transaction.
   Admission rechecks item/version/context records before adding the resolved canonical
   identity to the protected policy, preserving its allowance and all reservations.

   | Slot | Canonical budget target | Pinned job context |
   | --- | --- | --- |
   | Item | Exact `item_id`. | Originating captured ContextSnapshot version for that item, otherwise its admitted head. |
   | Storyboard frame | `storyboard-` + SHA-256 of RFC 8785 `[plan_id, shot_id, frame_id]`. | Explicit slot storyboard VersionRef and shot ID. |
   | Sequence entry | `sequence-` + SHA-256 of RFC 8785 `[sequence_item_id, entry_id]`. | Explicit slot sequence VersionRef and entry shot ID. |

   With a slot, request `target_id` is an alias/assertion retained verbatim in the command
   and provenance, not the ledger key. Renaming it or publishing a later version cannot
   reset the same frame/entry's allowance. Different actual slots receive distinct keys.
   Without a slot, an explicitly pre-bound target remains valid. Otherwise an existing
   real item is allowed, or `target_id == work.generation_task_id` identifies the task's
   **one standalone unstructured concept**. Other arbitrary new strings are denied.
   Multiple concepts use published storyboard slots. No fake source item is required.
   The verified identity, source-document hash and captured context are frozen in job inputs.

   An explicit owner allowance extension has a separate trusted transaction primitive:

   ```python
   extend_generation_task(tx, authenticated_owner_caller, task_id, new_limit,
                          owner_operation_id, expected_policy_storage_revision)
   # -> (policy_JSON, replayed)
   ```

   Invoke only from the owner's recorded instruction/permission transaction. It rejects
   tools, retains reservation history and records the owner and previous/new limits. No
   provider/native HTTP endpoint exposes policy creation or extension. Steer, delegation,
   corrections and Resume retain the originating work's task. Existing bindings cannot be
   silently overwritten, including after default settings change.
3. **Accepted W02 artefacts:** `extensions['artifacts']` implements accepted `get` and
   `ready_path`. Supply `registrar: Callable[[Caller, ArtifactRegister_JSON], Artifact_JSON]`
   to `install`. It receives an exact-attempt worker Caller allowing `registerToolArtifact`.
   Use exported `register_provider_artifact(services, caller, ArtifactRegister_JSON)
   -> Artifact_JSON` as the closure above. This does **not** call generic W02 `register`,
   mint a capability or convert the worker to tool/owner authority. It checks the original
   operation/body/project/job/attempt/input binding first for replay. New registrations
   require exact current JobRecord/JobAttempt identity and the `registerToolArtifact`
   allowlist. The source must be under `.proscenium/jobs/<bound_job_id>/`, pass secret and
   real-path checks, and be opened component-by-component without following symlinks.
   Bytes and declared hash must agree. Derived inputs must exist, be ready in this project
   and still match during commit. The bridge calls W02 `artifacts.promote` outside the
   mutation transaction, then W02 `artifacts.put(tx, artifact)` inside its idempotent
   receipt transaction. Image dimensions, transformations and the pinned source version
   are retained. Matching receipts replay after status changes or missing staging bytes.
   W07 never writes W02's `artifacts` namespace directly. Missing registrar produces
   `capability_unavailable` before inference. `ArtifactRegister` staging paths are relative
   managed `.proscenium/jobs/<job_id>/...` files. They are hash-named, exclusively created,
   fsynced and made read-only before registration. Reuse verifies bytes rather than
   overwriting them. W02 supplies final immutable storage and authenticated serving.
4. **Accepted W05 store:** `proscenium.reviews.install(services)` supplies `create(tx,
   ReviewRequest, job_id)` and `complete(caller, ReviewComplete)`. W07 calls create in its
   same job-admission transaction. Missing store is `capability_unavailable`. W05 owns
   findings, owner reads/rejection and `validate_and_submit_findings` in an authenticated
   owner's Queue transaction. Do not forward findings through the native tool response.
5. **Root composition:** import the router and service explicitly. Do not register
   `providers.generation` or `providers.review` with another generic outbox executor.
   W07's pump owns those kinds. Existing W01/F00 dispatchers must select only their kinds.

An owner request always creates a `vlm_review` job with `work_id=None` and
`owner_operation_id=review_id`, including while unrelated work is active. It creates no
native request/turn. A tool request inherits its authenticated work. Worker completion
checks exact job, attempt and input digest. Tool completion cannot complete an idle-owner
review. Only ticket/status is returned on every native-facing review route.

## Configuration

Public `Settings.services` entries retain their existing contract:

```json
{
  "provider_id": "configured-comfy",
  "endpoint": "http://configured-host:8188",
  "capabilities": ["image"],
  "model_id": null,
  "available": null
}
```

For LM Studio use capability `vlm`, the exact loaded instance ID as `model_id`, and the
service root as endpoint, **not** the `/v1` API suffix. Comfy endpoints may have an explicit
reverse-proxy prefix. No fallback address exists. Endpoint credentials, query tokens and
redirect-based endpoint substitution are forbidden. The exact provider endpoint/model and
execution settings are frozen through `jobs.freeze_inputs` before external work. Every
later poll/download uses `jobs.inputs`, not current defaults.

The only private `Settings.provider_options` keys currently supported are:

| Key | Default | Meaning |
| --- | --- | --- |
| `review_provider_id` | None | Choose exactly one configured VLM provider. Ambiguous choices are unavailable. |
| `minimum_free_vram_bytes` | 268435456 | Comfy pre-submit memory floor, alongside queue checks and the shared GPU claim. This is not a model-fit estimate. |
| `vlm_max_tokens` | 512 | Positive integer, maximum 512. |

No credentials are read from project files, environment files or reference checkouts.
Authenticated installations may inject a parent-managed HTTP client whose transport
resolves secret references out of band. Do not put credential copies into this dictionary,
job inputs, graph fields, artefacts, events or logs. Unknown execution-option keys are
rejected. No native/service authentication token is returned in a job or review ticket.

## Generation execution and recovery

- `GenerationSubmit.settings` is empty or contains only the normative `target_slot`
  described above. It cannot change execution options or budgets. The exact registered
  API graph is the execution specification. `workflow_artifact_id` names that graph and
  `prompt_artifact_id` names the UTF-8 prompt. Bind `$prompt` only to CLIPTextEncode text
  and `$seed` to a seed input. Seed must be a decimal integer in `[0, 2^53-1]`, because the
  saved API graph is RFC 8785 JSON. Null or inexact seeds fail before reservation.
- `tools/comfy/graph.py` prints an explicit FLUX.2 Klein text or one-reference graph. All
  model filenames/dimensions come from the task. There is no historical treatment/brief.
  `artifact:<id>` in LoadImage must correspond exactly to `input_artifact_ids` and reach
  the saved image through VAEEncode, ReferenceLatent and positive CFGGuider conditioning.
  Unused references and filename-only prose conditioning are rejected.
- The pump queries actual `/object_info` model/node choices, typed links and primitive
  bounds, then `/queue` and `/system_stats`. It also acquires F00's capacity-one
  `heavy-gpu` claim before upload/submission. External busy queues or cooperating claims
  produce `waiting_resource`, with the same reservation. Memory availability is observed,
  not an invented model-fit guarantee.
- Actual conditioning images are decoded, EXIF-oriented and encoded as RGB PNG. Original
  and derived hashes plus registered derivative artefacts are retained. The final uploaded
  filenames, exact graph, graph hash and client ID are saved before `POST /prompt`.
- Admission commits the stable job/attempt, budget reservation, frozen inputs and outbox
  intent before HTTP. No service call runs inside a DB transaction. A matching admission
  retry reuses the current job before reading changed defaults or unavailable providers.
- Known pre-execution failures release a reservation. Accepted/uncertain inference counts.
  Status, waiting, reuse and download reserve nothing. `retry_job` refuses image/mesh/VLM
  jobs through the accepted F00 restriction. A correction is a new budgeted submission.
- Prompt timeout leaves `outcome_uncertain` and its reservation/claim. Known prompt IDs
  use `/history/{id}`. Unknown acceptance searches queue/history by the durable unique
  client ID. No match is **not** proof of rejection. No fresh inference is submitted.
- Completed images are decoded/verified, staged immutably, registered through W02 and
  linked in `JobRecord.artifact_ids`. A metadata artefact contains exact graph/prompt,
  seed/model/input/derivative hashes and prompt/client IDs. The job pins an existing item's
  current version when available. W02 can expose that target-linked job in its version
  read model. Source/head and owner selection records are never changed.
- After verified provider terminal completion the shared GPU claim is released. Missing
  downloads/storage can still leave an uncertain job needing explicit recovery. A process
  crash in preflight/preparation is conservatively held rather than automatically retried.
  A pre-submit `checking`/`preparing` crash needs a host reconciliation decision. The pump
  never steals claims by age or replays an unknown effect.
- Comfy transport methods remain separate: `capabilities`, `upload`, `submit`, `status`,
  `wait`, `reconcile`, `download`. The diagnostic tools expose read-only preflight and
  graph construction, not an unbudgeted submit CLI. No lifecycle/queue-clearing route is
  implemented and no global interrupt is registered as job cancellation. Cancellation
  is honestly `cancel_unsupported` until a proven job-specific adapter exists.

`image_to_3d` is explicitly unavailable pending W09/E04. This module does not claim mesh
generation, edit source authoring or use a text graph as a substitute for reference input.

## Structured review and finding safety

- Only requested clean target images, criteria and explicitly named JSON telemetry are
  supplied. Image/telemetry hashes are frozen and checked again before inference.
  Image pixels are decoded and encoded as clean RGB PNG, with their sent hashes recorded
  in frozen inputs. No annotations, unrelated project content or automatic publication
  review is added.
- LM Studio `/api/v1/models` must show the exact configured instance already loaded with
  `capabilities.vision=true`. `/v1/models` alone is inventory, not vision/load proof. No
  model is implicitly loaded by the adapter. The actual call is OpenAI-compatible
  `/v1/chat/completions` with `response_format: json_schema` and a bounded response.
- The model supplies only indexed observations/recommendations and evidence. The host
  supplies finding IDs, project, review, immutable captured target, revision and unreviewed
  state. Wrong indices, added authority fields, truncated/malformed results, visual evidence
  pointing at another image and measurements without explicit telemetry fail safely.
- Validated findings go only to W05. Events and native responses contain ticket/status,
  not recommendation text. A transport timeout is uncertain and is never resubmitted.
  Validated completion is retained privately so a DB-completion retry needs no inference.
  The owner must submit exact approved text/revision/target through W05/W01's owner path.

## Provider-owned storage collections

No new physical table or migration is introduced. W07 owns only:

| Namespace | Purpose |
| --- | --- |
| `providers.tasks` | Host-frozen task limit and canonical targets. |
| `providers.policy_extensions` | Explicit owner allowance-extension evidence. |
| `providers.submissions` | Immutable generation command/work idempotency binding. |
| `providers.review_requests` | Review command/authority and admitted job binding. |
| `providers.tickets` | Private ticket projection for native retry responses. |
| `providers.pending` | W07-only job-intent index. |
| `providers.execution` | Private submission marker, graph/client/prompt or validated completion. |

Bridge receipts use operation scope `providers.artifact`; no new physical collection is
needed. Canonical target additions update `providers.tasks` with storage CAS and never
rewrite old job targets. Resolution helpers `providers.targets.resolve_target` and
`admit_target` are internal identity/admission functions, not native tools.

F00 alone writes job/attempt/input/evidence records. W07 calls its accepted API and ledger.
W02 alone registers artefacts. W05 alone stores review findings and owner submission links.

## Parent composition

```python
from proscenium.previews import PreviewService, install, router

previews = install(services)  # Requires accepted W02 extensions before execution.
app = create_app(services.settings, services=services, routers=[router])

# Safe at restart with the execution gate closed. Never launches a worker.
previews.reconcile(project_id)

# After explicit Resume has reconciled ownership and opened the F00 gate:
previews.pump(project_id)       # One explicit dispatch pass.
previews.start(project_id)      # Optional background receipt/dispatch watcher.

# On backend shutdown, before services.close():
previews.close()                # Stops watcher, not admitted detached workers.
```

- `install(services) -> PreviewService` is idempotent and sets `extensions["previews"]`. It starts nothing.
- `PreviewService.request(caller, PreviewRequest | validated_dict) -> (JobRecord, replayed)` accepts the generated RootModel or its normative JSON.
- `register(caller, FrameReceipt, segment=False)` and `register(caller, PreviewSegment, segment=True)` return `(CommandReceipt, replayed)`.
- `availability(project_id, job_id) -> FrameAvailability` computes intervals from actual registered receipts, never the highest frame number.
- `reconcile(project_id)` consumes existing exact-attempt journals, refreshes progress, reconciles launch acknowledgement loss and retains partial outputs on failure. It does not launch a native process or reopen the source in Blender.
- `pump(project_id)` consumes owned pending outbox rows. Its launch branches require the execution gate. Cancellation intents can run while the gate is closed.
- `start(project_id, interval=0.05)` runs reconcile/pump on a watcher. On a closed gate it can reconcile, but cannot launch. It is not installed implicitly in application lifespan.
- `close()` stops the watcher. Browser loss and backend closure do not terminate admitted supervisors.

### Required F00 atomic-update seam

The receipt transaction detects this **parent-owned** method when present:

```python
services.jobs.update_in_transaction(
    tx, caller, job_state_update_json,
    evidence="Verified immutable worker receipt",
)
```

It must implement F00's existing attempt/caller/CAS/state/evidence checks, update the job/attempt/evidence records and emit `job.state_changed` using the supplied transaction, without opening another connection. Its public wire input remains `JobStateUpdate`. W03 builds that existing DTO after inserting the ready artefact and receipt. Failure rolls back the complete receipt transaction. An offline injected-failure test verifies the seam's transaction placement. The method is **absent at the accepted base**, and was not silently implemented with a competing W03 job store.

Until the parent supplies it, `preview_progress` is the authoritative atomic media-availability revision and F00 job progress is an eventually reconciled projection. Native evidence below used this explicitly documented fallback.

## HTTP operations and caller scope

All six assigned operation IDs are exported by `router`:

| Operation | Route | Caller |
| --- | --- | --- |
| `getFrameAvailability` | `GET /api/v1/projects/{project_id}/jobs/{job_id}/availability` | Owner |
| `listFrameReceipts` | `GET .../jobs/{job_id}/frames` | Owner |
| `listPreviewSegments` | `GET .../jobs/{job_id}/segments` | Owner |
| `requestPreview` | `POST /internal/v1/previews` | Tool |
| `registerFrameReceipt` | `POST /internal/v1/frame-receipts` | Worker only |
| `registerPreviewSegment` | `POST /internal/v1/segments` | Worker only |

Reads are paginated with F00's scoped cursors. Frame filters are inclusive `from_frame`/`to_frame`. Preview requests return 202 initially and 200 for an identical existing operation/intent. Receipt commands return 201 initially and 200 on an identical replay. JSON command identity must match `Idempotency-Key`.

Tool admission requires `requestPreview`, the active project, current owner epoch, original work and invocation ID. W02's `admitted()` checks the persisted invocation association and open work/gate. Same-operation replay precedes new-admission checks. `preview_intents` is shared with W02 publication, so an initial publication intent cannot be duplicated by later `requestPreview`.

Worker receipt authority binds project, job, attempt, input digest, version, shot and source interval. The host can issue an HTTP worker token out of band using `services.auth.issue_capability(worker_caller(job))`, where `worker_caller` is exported from `proscenium.previews.service`. It grants only the two receipt operations and `updateJobState` for that exact admitted attempt. Tool/owner credentials cannot authenticate worker receipt routes. No worker token is placed in a public job, event or media file.

The built-in detached worker uses a private, exact-attempt filesystem journal and the trusted reconciler rather than posting bearer tokens over HTTP. The reconciler derives worker authority from the original persisted job and validates the bound task/root/input identity. It never guesses an originating tool invocation from current work.

## Native admission, publication and recovery

- `sources.materialise(project_id, version_id)` supplies the sealed immutable source closure, not live working files. The fixed Blender worker rehashes declared bytes, verifies application/version/build/features, performs Blender's external dependency traversal before rendering and rechecks dependencies at each source frame and after completion.
- Linked libraries, textures and material image-sequence users must resolve to declared hashed files. Scene/world/light/group image nodes are inspected too. Saved stateless Geometry Nodes modifier graphs are classified separately from simulation, as described below. Unsupported simulation/bake/cache/import nodes, external volumes/cache datablocks, UDIM closure and compositor image sequences without an inspectable image user remain rejected, not rendered with undeclared data.
- F00 storage reserve and estimated output size are checked before launch. A cooperating F00 resource claim and an OS-held `blender-render.lock` protect one owned native writer. Each attempt also has an exclusive output lock. FFmpeg encoders have an additional OS-held encoder claim.
- A persistent `launch.claim` fences the spawn-before-acknowledgement window. An ambiguous launch is never automatically repeated. Supervisor and native process journals record PID, `/proc` start ticks and argv. Missing identity is uncertainty, not a guessed exit code.
- Workers use factory startup, disabled auto-execution, a fixed installed entry point and validated structured data. Publication cannot nominate shell strings. Render overrides exist in memory only. There is no source-file save.
- `camera: null` keeps authored camera animation and timeline camera selection. A static override is reapplied after frame evaluation so authored camera markers cannot replace it. Perspective/orthographic optics, clipping, aspect, rigid metre-space pose and shift must reproduce the authoritative row-major projection matrix.
- Each PNG is completed before its immutable receipt is written. W03 verifies output-root containment, symlinks, bytes, decoded PNG RGB8 dimensions and input binding, then promotes immutable bytes using W02. The receipt, artefact record, media availability revision and event commit together.
- Four-frame independent silent H.264/yuv420p MP4 segments encode on one background encoder while Blender continues. Rational rate numerators set the MP4 track timescale. Full decoding, initial keyframe, exact PTS, rate, count and dimensions are checked before publication.
- Available/pending/failed intervals partition actual source frames. Playable ranges are only the registered segment intervals covered by ready frame receipts. Failure/cancellation preserves completed artefacts.
- Cancellation is registered for render and W03-owned encode jobs. Parent dispatch of `job.cancel` must route only to the appropriate owning adapter. The supervisor observes the exact-attempt cancellation marker and kills only its own native process group when needed. A completed native result wins the cancellation race. No global process killing exists.
- F00 retry must first prove a failed/cancelled terminal attempt. W03 queues the new attempt's owned launch intent and copies only registered, hash-verified same-input frame artefacts for reuse. Old attempts remain in history. Late identical old receipts are acknowledged without mutation. Other old-attempt writes are rejected.
- A surviving exact worker can be observed while the gate remains closed. A lost supervisor with no trustworthy terminal journal remains `outcome_uncertain`; the adapter does not invent a native exit code or grant a retry. Live orphan termination and workstation-loss recovery need broader native fault acceptance.

## Static proxies

Proxy jobs export a static GLB and normative `ProxyMapping`. IDs must already exist in authored custom properties. Object names and glTF indices never become invented source identities. Mesh instances can share an object ID, but instance IDs must be unique. Ambiguous collection/particle instances are rejected by this profile.

Mapping paths are **child indices from the glTF scene root**, matching W05's consumer. Mapping matrices are flattened row-major proxy-world metres. Blender's Y-up export is verified against actual GLB nodes/geometry. Artefacts are linked through the render job and `version_links`, without changing the source publication.

## Trusted assembly tool

No additional endpoint or competing wire schema is introduced:

```python
job, replayed = previews.assembly(
    caller,
    job_admission,      # Normative JobAdmission, kind="encode".
    sequence_map,       # Normative, already published SequenceMap.
    frame_map=None,     # Normative full FrameMap for explicit holds/drops/dissolves.
)
```

W01 can bind this callable as a trusted native SDK tool with the host's original `Caller`. It requires `admitToolJob`, the same configured execution profile, admitted work/invocation and the source sequence version in `JobAdmission.target.version`.

`input_artifact_ids` must be exactly the unique source receipt artefacts. `input_digest` is RFC 8785 SHA-256 of:

```text
{
  sequence: <SequenceMap with optional entry.choice labels removed>,
  frame_map: <complete FrameMap>,
  input_frames: <exact FrameReceipt objects sorted by artifact_id>
}
```

`assembly.expand(sequence_map, None)` deterministically constructs full cut/trim maps. Explicit retime/transition maps must agree with the sequence's already published mapping artefacts. W02's semantic validator checks destination partition, complete rows, reduced weights, source-job/version/shot/range associations and identity mappings. W03 additionally requires distinct dissolve shots, ready pinned contributor frames and common dimensions. There are no inferred frames, optical-flow interpolation, implicit resizes or holes.

Admission uses F00's `JobService.admit`. W03 stores its immutable assembly snapshot and original invocation association before enqueuing `preview.assemble`. A crash between admission and that feature snapshot leaves an unlaunched planned job, not permission to guess inputs. A matching original tool retry can finish admission.

The detached encoder copies verified source PNGs, performs explicit hold/drop selection and weighted **linear RGB** blending, then re-encodes sRGB review frames to silent H.264. It registers a final video, full `frame_map` and manifest with exact source receipt lineage. `version_links` makes these visible without replacing the sequence version or earlier annotation targets. The in-process adapter supplies explicit terminal evidence; it does not invent a Blender exit code for an encode job.

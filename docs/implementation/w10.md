## Recovery contract

```bash
uv run python -m tools.operations.recovery backup --project-id PROJECT_ID --target /new/private/backup
uv run python -m tools.operations.recovery verify /new/private/backup
uv run python -m tools.operations.recovery restore /new/private/backup --target /new/disposable/recovery --rebind-fresh-registry
uv run python -m tools.operations.acceptance --release
```

- The relevant service must be stopped and all work/invocations/decisions/jobs
  settled. Held Queue requests survive. Uncertain dispatch/resource claims refuse
  backup. No cancellation, signal, service start/stop or implicit reconciliation is
  attempted by the CLI.
- Registry/project locks use the exact F00 `owner.lock` flock identities and remain
  held throughout backup. The source lock contents are not replaced with a fake
  owner epoch. Scoped processes or ambiguously attributable native Copilot cause
  refusal. Uninspectable living same-user processes cause refusal, except identified
  OS session/auth daemons which cannot be application workers. Independent unrelated
  editor/model services are neither killed nor used as proof of product readiness.
  The pinned SDK's explicit `COPILOT_HOME` disambiguates unrelated native homes.
  Observed terminal kernel states handle exit-time `/proc` races without inventing
  a successful job exit. Known privileged `runc` namespace initialisers are host
  infrastructure, not this V1 host-native worker implementation.
- Both SQLite stores use **F00 `Store.backup()`**, not main-file copies. Backup only
  accepts the exact current migration revision and does not migrate source stores.
  Sanitised backup databases are committed, vacuumed and closed in DELETE journal
  mode before hashing. Tests specifically caught and fixed a WAL sanitisation trap.
- Registry output keeps only the selected project binding and non-secret owner
  settings. Pairing/cookies/capabilities/cursor secrets and other projects are not
  copied. The project database retains requests, context, catalogue, notes,
  selections, provenance, approvals and original acknowledgement receipts.
- Git bundle covers all refs/HEAD and their complete reachable object closure.
  Every historical LFS pointer blob is read directly from Git, then the original
  local LFS bytes are streamed/hash-verified. No fetch/push/filter/hook/stash/reset
  runs against the original. The original index/unrelated staging is byte-preserved.
  Current ordinary working files are copied separately. Dangling/reflog-only objects
  and original staging are not recovery authorities. Unreachable published commits,
  alternates, shallow repositories and linked-worktree Git stores are refused.
- Ready registered artefacts, retained source bytes and private project tool spills
  are copied. Source/native/managed files are streamed in 1 MiB chunks. Missing
  registered media, retained sources and native history have separate limits.
  `--allow-incomplete` is explicit at backup **and** restore. Hash corruption never
  becomes an acknowledged missing-byte success.
- Exact native IDs come from association/work/event records under W01's configured
  `data_directory/copilot-runtime/home/session-state`. Only those complete session
  trees are copied, not the shared home/auth/retrieval stores. Pinned proof-directory
  **metadata**, not private history content, established the layout. Nested history
  archives are included. External/symlinked layouts are refused. Transient `.lock`
  files are not history. No native history content is supplied to an LLM.
- Output manifests record stable IDs, exact refs/commits/LFS OIDs, schema revisions,
  relative paths/hashes/byte counts, installed SDK version, lock-only CLI version/
  hash and non-secret configuration/profile references. The pinned SDK is required
  for this layout adapter. This is not a new native runtime/version execution proof.
- Backup/restore roots must be new and canonical. Inventory, traversal, symlinks,
  special files, credential paths, unexpected payloads and corrupt hashes refuse
  restore before activation. All backup/restored directories are `0700`, files
  `0600`. Failed targets remain private, never automatically deleted/reused.
- Restore changes location only in a **fresh isolated registry**, retains project/
  repository/session IDs, marks `awaiting_resume` and opens no gate. Git LFS filters
  are installed only in the fresh restored repository, with smudge/hooks skipped.
  No remote credentials/configuration, original hooks or owner cookies are copied.
  New owner pairing and supported machine-private login are separate operations.

## Acceptance orchestration and parent integration

1. **F00 composes the accepted application.** All 53 operations/lifespans, atomic
   job receipt update, native-session projections and mutation locking remain with
   the parent. W10 does not patch these seams or inspect uncommitted worktrees.
2. **Native recovery proof remains allocated to the parent.** Run the restored
   real session's reconcile-only history read, check old/native absolute path
   references and then explicitly authorised continuation. No fresh session fallback
   or native inference-resume pass is claimed by this package.
3. **Promote required outputs before backup.** Settled job/snapshot caches are
   excluded. Only registered/retained media are authoritative. Reconcile/promote a
   sole unregistered worker result through the owning adapter, not by treating its
   working directory as an undeclared published artefact store.
4. **Root acceptance invocation is parent-owned.** The standalone command in
   `docs/development.md` already works. Add it to the root build/CI only from the
   integration-owned configuration. No model/browser test is launched by validation.
5. **Current backend CLI flags are documented exactly.** If the parent adds dynamic
   configuration/settings flags, update `docs/operator.md`'s current CLI table,
   recovered-config instructions and the service template together. Do not invent
   flags ahead of the accepted implementation.
6. **Evidence stays separated.** C01–C31 resolve to real function definitions.
   Offline JUnit records observations only. Native/browser/SSH/performance journeys
   require separate exact-revision artefacts and explicit evidence types. The
   release validator refuses incomplete evidence and records M10 as blocked unless
   an actual native mesh proof or explicit human-owner scope record is supplied.

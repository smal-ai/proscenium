## Failures and exact deviations

- The first `loop-v1` render failed with `dependency_missing`, native exit 1,
  before producing a frame. Blender factory tool settings retained two weak
  references to installed `essentials_brushes-gp_draw.blend`. Production closure
  validation correctly refused paths outside the materialisation.
- One authorised cloud correction removed unused factory tool-setting references
  in the **owned source**, preserved the scene objects and published a new
  immutable `loop-v1-clean`. The failed `loop-v1` and its job remain retained.
  The demonstrated visual loop is therefore `loop-v1-clean` → `loop-v2`, not a
  fabricated successful render of the original `loop-v1`.
- CDP clears viewport emulation on disconnect. The first two Send actions used
  Chromium's default 780 × 380 viewport. The fixture was corrected to set the
  viewport on every connection before any interaction. Do not describe this as
  an uninterrupted Full-HD run from the first prompt.
- The fixture's first pin click incorrectly used the letterboxed element bounds.
  It was erased through the actual editor and replaced using the contained-image
  rectangle. The submitted saved annotation has exactly **one** pin, on a measured
  blue pixel. No wrong draft was submitted to the model.
- No shared schema, database, job reducer, router, lifecycle or UI implementation
  was changed. No competing source/publication service or renderer bypass exists.

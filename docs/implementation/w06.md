### Read-only CLI

Run with the installed application package (`uv sync --frozen`):

```bash
uv run python agent/skills/storyboard/plan_tools.py validate <authored-plan.json>
uv run python agent/skills/storyboard/plan_tools.py compare <before.json> <after.json>
uv run python agent/skills/storyboard/plan_tools.py impact <plan.json> --changed-id <id>
```

Validation uses `proscenium.contracts.validate("AuthoredShotPlan", ...)`. Missing
IDs/unknown fields fail the shared schema. Additional semantic checks reject duplicate
shot/frame IDs, reversed source ranges, out-of-order frame roles and an available
frame without an image ID. Compare preserves its inputs and reports changed/removed
shot/frame IDs and affected downstream image/scene-version IDs. Array reordering
conservatively affects assembly dependants. Global brief/treatment/asset changes
conservatively affect all shots because contract 1.0 has no per-shot asset graph.
Unknown external dependants require catalogue/source dependency inspection, not an
invented graph. The helper has no network, process, generation or write operations.

### Frontend

```tsx
import { StoryboardBrowser } from "./features/storyboards";
// Parent-owned composition:
// <StudioApp components={{ ..., storyboards: StoryboardBrowser }} />
```

`StoryboardBrowser` matches accepted `ReviewSurfaceProps` and uses generated
`ApiClient` operations only. It follows pagination for catalogue items, storyboard
versions, selection records and render-frame receipts. It shows historical plan and
version IDs, authored scene/version/range/fps, ordered intermediate reference roles,
missing/proposed/image availability, unresolved inputs and render-source staleness.
New catalogue heads are labelled without adopting them. There is no review-duration
field, GPU admission, generation endpoint or rebuild-triggered production operation.

The panel fits a real 280px left column at 1920 × 1080 with internal plan/action
scroll regions and readable 12–13px metadata. The parent owns column allocation.
`onQueue` receives explicit planning, concept or scene requests and is awaited when
it returns a Promise. The planning action expressly forbids production execution.

## Exact owner-selection behaviour

- `SelectionSave.slot` is `storyboard_frame` with exact storyboard item/version,
  shot ID and frame ID. The choice is an artefact identity, never an item/version
  shortcut. Supersede/withdraw retains the slot's selection ID and current revision.
- Alternative image IDs are resolved through owner `getArtifact` and must identify
  ready active-project images with dimensions. Selection does not rewrite a plan.
- `owner_selected` is derived from the exact selected slot **and the authored frame's
  current artefact ID**. An alternate owner choice is displayed separately, can be
  reviewed, and does not make the original authored image owner-selected.
- A new storyboard version starts a distinct slot even when all authored IDs match.
  Withdrawal keeps history. No agent-authored `selected` state is treated as an
  owner event.
- Transport uncertainty retains the immutable command and offers explicit exact
  retry. No automatic mutation retry. Definite validation/permission/CAS rejection
  reloads authoritative state before another choice. Pending commands live in the
  mounted component, not a second durable browser selection store. The backend
  remains responsible for slot uniqueness, CAS and idempotent reconciliation.

## Parent integration and remaining needs

1. **W04 composition:** supply `StoryboardBrowser` as `StudioComponents.storyboards`.
   Frame clicks call `onNavigate(exactStoryboardVersion, turnSelection)`. That callback
   opens the version centrally. Only when absent does the component fall back to
   `onContextChange`. The accepted optional callback resolves the original seam gap.
2. **W05 central review:** honour supplied `selection.target` rather than selecting
   a version's first image. Reference/concept targets carry exact artefact/hash/
   dimensions and matching `Attachment`. The parent keeps the storyboard version
   as the navigation record while a render target identifies its actual scene
   version and source frame. No shared types need changing.
3. **Render context:** pass the relevant project render jobs through the accepted
   `jobs` prop. W06 reads their paginated frame receipts and verifies artefact ID,
   hash/dimensions, project, job, input digest and source-version association. It
   never infers a source frame from array order, the authored range or a filename.
   Without a matching receipt/job it displays the image but explicitly withholds
   an invented render target. Historical jobs omitted by the parent can therefore
   leave render context unavailable until those jobs are supplied.
4. **W02 catalogue/source:** implement/combine accepted owner `listItems`,
   `listItemVersions`, `getVersionShotPlan`, `getArtifact` and media routes. Supply
   published source commits and immutable plans through the source tool chain.
5. **W05 selections/W03 receipts:** integrate accepted `listSelections`,
   `saveSelection` and `listFrameReceipts`. The package does not register routes,
   migrate storage or replace these services. Missing capabilities remain errors.
6. **Skill registration:** parent runtime composition must expose both skill resource
   directories and accepted source/checkpoint/publication tools to the lead agent.
   Asset MCP discovery/import and Blender validation still need integrated native
   journey evidence. Optional unavailable BlendSwap is not a failure of local search.

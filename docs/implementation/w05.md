# W05 review surfaces and persistence

Implemented against accepted foundation `7b95381`, then fast-forwarded to the
accepted navigation/async-submission seam `f50a743`. Contract 1.0, specification
3.2.0. All W05 changes are on `impl/w05` in the assigned worktree. No shared
schema, physical migration, router composition, provider or shell-module edits.

## Parent composition

```python
from proscenium.reviews import install, router

install(services)  # Idempotently registers services.extensions['reviews'].
app = create_app(settings, services=services, routers=[router, ...])
```

The router implements exactly `listAnnotations`, `saveAnnotation`, `listSelections`,
`saveSelection`, `listOwnerReviews`, `listOwnerReviewFindings` and
`rejectReviewFinding`. Every handler authenticates the owner. W07 owns owner/tool
review admission, job execution and completion HTTP routes. No read launches a
provider, native application or repair.

```ts
import { ReviewWorkspace, Outliner, CriticPanel } from "../features/review";
import { CatalogueBrowser } from "../features/catalogue";
```

These implement the integration-owned `api/studio.ts` props. The parent installs
them in `StudioComponents`. Explicit external targets are consumed through
`selection`. Saved-annotation navigation uses `onNavigate` when available. Ordinary
receipt refreshes do not move the primary target. Queue/Steer promises are awaited
before marking feedback submitted. W05 does not import unaccepted W04 files.

## W07 review-store transaction seam

```python
ReviewStore.create(tx: Transaction, request: dict, job_id: str) -> dict  # ReviewTicket
ReviewStore.complete(caller: Caller, request: dict) -> dict             # ReviewTicket
```

- `create` is a trusted primitive, not an owner-authorisation endpoint. W07 first
  authenticates its owner/tool admission, creates the exact `vlm_review` job and
  calls `create` in that **same transaction**. The job target ID equals `review_id`.
  The original `ReviewRequest`, targets and telemetry IDs are immutable.
- W07 retains responsibility for owner `work_id=None` / `owner_operation_id`, job
  status, provider dispatch and cancellation. A review-store result contains only
  `ReviewTicket`. Findings never appear in tool results or public events.
- `complete` consumes `ReviewComplete`, checks the original project/review/target,
  initial finding revision/state and exact worker job/attempt/input digest, or
  admitted tool work. The caller must permit `completeToolReview`. Measured evidence
  requires an originally supplied telemetry artefact. Original observations and
  all subsequent finding revisions remain retained.

## W01 atomic owner finding submission

```python
reviews.validate_and_submit_findings(
    tx: Transaction,
    request_id: str,
    approved_findings: list[dict],  # Generated ApprovedFinding JSON
) -> None
```

Call this **inside acceptance of an authenticated owner's Queue/Steer request**,
on the same F00 transaction as the immutable request, context, event and dispatch
intent. Never call it from an unauthorised tool callback. It checks:

1. Unique finding IDs, the exact current finding revision and canonical target.
2. Ready review status, the original project and non-submitted finding state.
3. Exact target image ID/hash/dimensions, source version, render job/shot/frame or
   explicit sequence map, and referenced ready media.
4. An immutable submission link to the request and original approved text/revision.

A same-request/same-list retry returns without a second transition, even after
newer revisions exist. Changed reuse conflicts. A second request cannot reuse a
submitted revision. Rejected findings can be explicitly submitted at their new
current revision, retaining their rejection history. If any later acceptance step
fails, SQLite rolls the findings and links back with the request.

W01's context validation must also require each approved target's original image
in the accepted attachments. `ApprovedFinding` does not carry an attachment list,
so this method cannot validate a list it does not receive. The UI supplies those
exact images and visual evidence images, without forwarding unchecked advice.

## W02 dependencies and derived selections

- Registered artefacts, versions, jobs, frames and segments use F00 namespaces.
  `ArtifactService.ready_path` supplies registered mask/mapping bytes for hash and
  content validation. No second upload service is introduced.
- A mask may be registered as `mask` or as an ordinary image upload. Its accepted
  role comes from the explicit markup reference. In both cases the store requires
  PNG, Pillow mode `L`, exact dimensions, matching bytes/hash and binary/soft pixel
  semantics. An RGBA file named `mask.png` is rejected.
- Storyboard and assembly slots use `SourceService.materialise(project, version)`.
  A returned directory is resolved to the version's source entry, a returned file
  is read directly. Storyboards validate as `AuthoredShotPlan`, sequences as
  `SequenceMap`. The materialiser must be a read-only historical-source operation,
  never an authoring/provider dispatch. No guessed W02 private namespace is used.
- W02 can call `reviews.owner_selected(tx, storyboard_version_ref, shot_id, frame)`
  while deriving its `ShotPlan` read model. This checks only the exact versioned
  slot and image choice, without altering the authored plan. It returns false for
  a different image, missing slot, withdrawn choice or different storyboard version.

## Persistence and revision mapping

- Annotations store the generated `AnnotationSnapshot`, not a competing DTO.
  Incoming `expected_revision=0`, `saved_revision=null` creates wire revision 1
  at F00 storage revision 0. Updates use wire revision minus one for storage CAS.
  Targets and ancestry are immutable. Old operation retries bypass current CAS
  and return their original acknowledgement. Conflicts do not mutate records.
- Selection slots are keyed by SHA-256 of canonical JSON, inside their project
  store. A new selection ID cannot bypass an existing slot. Selection wire and
  storage revisions both start at 1, using a transaction-local revision-zero
  reservation before the first schema-validated record. No reservation is visible
  after a failed transaction.
- Additional W05 record namespaces: `review.requests`, `review.annotation_history`,
  `review.selection_slots`, `review.selection_history`, `review.finding_history`,
  `review.submissions`. These use F00's existing records table. No migration needed.

## Browser behaviour

- Exactly one visible mode. Keyframes default when available. Form focus isolates
  shortcuts. Number keys select modes, Space toggles animation, arrows step exact
  ordinals without skipping missing frames, Shift+arrows change published shots.
- R3F loads the published GLB and uses OrbitControls. Proxy node paths resolve
  stable object/instance pairs. Outliner and pick selections share those pairs.
  Hardware draw-instance indexes are deliberately not invented stable IDs.
  Camera world basis converts proxy to Blender before row-major serialisation.
  Render this view queues that exact camera and pinned sample-frame range.
- Current/next independent MP4 elements are bounded to two. The predecoded element
  is reused at a boundary. Playback waits for a new rVFC-confirmed first frame
  before continuing. Timestamp quantisation tolerance is 0.0001 frame, verified
  against the actual F03/F04 ordinal cells. No MSE packaging is assumed.
- Availability explicitly distinguishes available/playable/pending/failed ranges.
  A missing middle interval is never replaced by a later segment. Pausing remains
  authoritative when a late segment arrives. Normal completion keeps the final
  target instead of inventing a pending frame beyond the known range.
- Annotation starts from decoded image dimensions or actual rVFC presentation.
  It pins image/version/job/shot/frame/camera/range independently of navigation.
  Letterboxing and DPR map through CSS content bounds to top-left image coordinates.
  Stroke width is in image pixels. Markup, clean source and canonical greyscale
  mask are separate artefacts. The GL framebuffer/source image is not painted over.
- IndexedDB retains draft snapshots, blobs, upload identities, original save
  operation/revision, acknowledgement and conflict state. Explicit retries and
  online-event retries use the original operation. Interrupted saves are recoverable.
  Conflict rebasing requires an explicit comparison and retains the superseded
  operation in the local draft. Saved drafts can be restored across navigation/reload.
- Complete sequence video capture uses an rVFC-captured intrinsic canvas image,
  registered only on explicit annotation. `FrameMap` resolves the sequence ordinal.
  Composite targets retain null `source_frame`, `shot_id` and `render_job_id`.

### Main-chat annotation preparation

- Workspace is the sole owner of `onContextPreparer` registration. Its stable
  handler reads the current viewer context, or delegates internally to the active
  editor. Editor mounting, typing and saves do not repeatedly register shell
  handlers. Workspace clears the registration on unmount.
- The editor captures a detached `Draft`, target identity, markup canvas and binary
  mask pixels synchronously at invocation, before any await. Upload/export/save
  awaits operate on that capture, not on a later viewport or draft. A navigation
  unmount cannot replace the returned target.
- The registered handler uses the same preparation function as Save. It persists
  blobs, reuses original upload/save IDs from the existing IndexedDB outbox, waits
  for the saved acknowledgement and returns a detached full `annotationContext`.
  Failed or conflicted saves reject. There is no silent `annotations: []` fallback
  in the registered Send path.
- Editor edit/save/queue controls share in-flight guards. A per-draft outbox guard
  also prevents reconnect handling from creating a parallel save in the same tab.
  Clean media remains the original registered image. Imported raster mask IDs and
  bytes are preserved. Editable vector masks use the canonical greyscale exporter.
- Tests compose the actual accepted W04 `ChatPanel` and `useRequestComposer` with
  ReviewWorkspace. They prove that annotation save precedes context/request
  admission, and that original chat text plus additional user-upload attachments
  survive navigation during an upload. No runtime/model is called.

### Catalogue selection recovery

- `proscenium-catalogue-v1` IndexedDB privately retains one original generated
  `SelectionSave` per project. Its operation ID, selection ID, typed slot, choice
  and expected revision are persisted before the first network effect.
- Network/timeout/5xx uncertainty keeps the command and blocks new owner-selection
  changes. Reload restores that command. **Retry original selection** sends those
  same IDs and body. **Reconcile selection status** reads authoritative records,
  but a matching choice is not treated as proof of the uncertain operation.
- Known unadmitted validation/CAS failures clear the pending command and reload
  authoritative choices before enabling a new explicit choice. Conflicting
  idempotency evidence stays blocked. An acknowledgement whose subsequent read
  fails is retained as acknowledged and reconciled without another mutation.
- IndexedDB initial reservation uses `add`. Updates/deletes compare the original
  operation ID in one transaction, so a late response from another tab cannot
  overwrite a newer pending command. No owner choice is inferred from viewing a
  version or from an older command receipt.

### Real proxy capture and Queue

- The internal ProxyView binding becomes available only after the actual published
  GLB has loaded. Picks use its mapped scene-node paths, retaining both stable
  object and instance IDs. No geometry substitute or invented spatial hit is used.
- Explicit **Render this view** freezes the source version/sample, selected pairs,
  actual framebuffer pixels and camera before its first await. It explicitly
  renders the existing inspection scene, then synchronously copies the framebuffer
  to a detached canvas before WebGL's default drawing buffer can be discarded.
  PNG encoding does not read a later frame. It does not paint over the WebGL canvas
  or pretend that the inspection lights are a Blender material render.
- Fractional CSS bounds and DPR can produce a drawing buffer whose aspect differs
  from the CSS rectangle. The capture sets the camera projection and renderer
  viewport to the exact intrinsic width/height. The captured camera remains
  Blender-world metres, row-major, with its authoritative OpenGL projection.
- The frozen PNG, hash, dimensions, camera, sample frame, selected pairs and stable
  upload ID are retained in private IndexedDB `proscenium-proxy-captures-v1` before
  upload. A failed upload retries those same bytes/ID, including after reload and
  a different live orbit. The upload acknowledgement must match project, ready
  image/PNG state, byte count, SHA-256 and exact dimensions before Queue is called.
- The resulting ordinary `TurnSelection` contains `FrameTarget.origin=proxy_capture`,
  exact source version/sample frame, actual PNG identity/dimensions, the captured
  `Camera`, and a `reference` attachment. It contains no false `SpatialHit`.
- Handoff is recorded before awaiting the existing `onQueue` promise. An uncertain
  submission retains its capture and directs the owner to the original Copilot
  request. It cannot be automatically queued again. The explicit local dismissal
  is labelled **after resolving Copilot request** and does not cancel that request.
- Mode changes remain read-only. No render/provider job is admitted by loading the
  GLB, orbiting, picking, searching or refreshing metadata.

### Catalogue and pinned metadata

- Search is case-insensitive over the already-loaded `ItemRecord` name,
  description, tags and provenance fields. It introduces no HTTP search query.
- Source URL, creator, licence and provenance note are visible. Missing values say
  `Unknown`. Only HTTP/HTTPS source URLs become links, with `noopener noreferrer`
  and `_blank`. Other strings remain escaped plain text. Unknown licence metadata
  never disables owner selection. Historical versions display their own recorded
  provenance rather than borrowing the current head's provenance.
- Workspace refreshes the same pinned `VersionRecord` through paginated
  `listItemVersions`, checking item/project/source digest/commit. It does not adopt
  a newer head. Ready artefact discovery unions that version's IDs with the current
  same-version jobs' IDs, including late links without a job revision change.
- Existing target/draft and visible proxy/sample/orbit remain pinned. A metadata
  refresh cannot replace an already validated GLB or erase it because a read went
  offline. Catalogue history/current/owner-selected labels remain separate.

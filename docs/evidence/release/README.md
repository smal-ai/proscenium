## Reading the index

- `sources[].application_commit` identifies the recorded tested commit **or recorded
  baseline**, as qualified by `identity_meaning`. Several old runs used uncommitted
  candidate drivers/UI over a committed base. Their explicit source/compiled hashes,
  missing pre-format hashes and staged runtime corrections remain visible. A base
  is never asserted to identify all executed bytes.
- `sources[].facts` contains values extracted by exact JSON pointer from committed
  original evidence. `recorded_commands` keeps the original path/pointer so a retained
  test command, setup command or worker argv cannot be confused with a live model call.
  Where no exact launch shell command was exported, `command_reference` points to
  the original native invocation bodies or documented entry point. It is not a
  reconstructed launch observation. Parent receipt activation must retain that
  distinction, not promote a verifier command into a native execution command.
- `cases[].invariants` quotes every normative scenario clause. Each names mapped
  offline nodes, native supports and installed-browser supports separately. An empty
  native support list means the clause is supported at another layer or needs parent
  scope review. It does **not** invent an extra live test requirement.
- Case-level node mapping is not proof that each node covers every clause. Actual
  JUnit observations are in `report.partial.json`. Native evidence does not turn the
  synthetic branches of those tests into model execution.
- `historical_failures` hashes original failed records separately. Failed attempts
  are not inserted as the current passing observation. No old status/limit is edited.
- Source cards can contain several executions. Before activation, split a cumulative
  receipt into the original tested identities where needed. Never assign one run's
  commit to another run just because both are in the same folder.

### Applicability recipe, no assumed equivalence

The unchanged policy supports `reviewed_ancestor`, `source_hashes` and
`reviewed_cherry_pick`. A record uses `format=proscenium-applicability-1`, exact
`receipt_sha256`, original `tested_commit`, explicit `accepted_commit`, final
`integration_commit`, `reviewer=coordinator`, `decision=applicable`, a specific reason,
mode and nonempty distinct hash-verified `validation_artifacts`. These are **parent
decisions**, not values granted by this draft.

- `reviewed_ancestor`: explicit reviewed lineage plus applicable distinct regressions.
  Being an ancestor does not itself approve every changed subsystem.
- `source_hashes`: exact named hashes must match both tested and final committed files.
  This is not usable to pretend an uncommitted overlay equals its base. Retain the
  original overlay identities and choose an honest reviewed disposition.
- `reviewed_cherry_pick`: supply the exact original/accepted merge base and a complete,
  ordered pair for **every** linear tested-branch commit after that base. Each entry
  contains `tested_commit`, `integrated_commit`, `patch_sha256`. Use the policy's
  exact edit digest, not whitespace-insensitive `git patch-id` or subject matching.

`tools.operations.release_inputs.cherry_pick_proposal(root, receipt, candidate, pairing)`
expands an **explicit supplied pairing**, calculates both-side exact patch digests through
the policy checker, checks full ordered lineage, candidate ancestry and distinct committed
regression hashes. `pairing` supplies `accepted_commit`, `common_base`, `reason`,
`validation_artifacts` and ordered `patches` with tested/integrated commits. It never searches
for plausible equivalents. Its output deliberately has `reviewer=null`, `decision=pending`.
Only the parent may review/activate it. The parent's five previously verified transferred-edit
comparisons are not guessed or reconstructed into a new approved map here.

Main-only evidence inspection uses hash-verified committed M13 outputs and explicit SSH
accepted mirrors/retained inert `.txt` sources. Original executed IDs remain original.
The builder does not require the fleet-only original Git objects. **Active applicability
validation does require known original tested commits** under current policy. If a final
portable checkout lacks those objects, the parent must retain/provide the original history
through its authorised source-retention process or disposition that provenance gap. Do not
replace `application_commit` with an inspection mirror to make validation pass.
